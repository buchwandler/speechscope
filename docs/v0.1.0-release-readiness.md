# SpeechScope v0.1.0 release readiness (unreleased)

**Decision: NO-GO for tagging or publishing.** This note records validation of the implementation against `SPEECHSCOPE_V0_1_0_RELEASE_REVIEW.md`. A staged `0.1.0` build is not a tag-derived release, and no release has been tagged or published.

## Implemented and locally validated

- Phase A correctness/safety changes: timestamp-safe exports, input preflight before backend construction, deliberate empty-policy and coverage semantics, and validated provider results.
- Phase B Redux policy: mocked Photon contract and lazy-import tests, encoded-WAV pass-through provenance, supported model/device constraints, and optional SDK compatibility workflow.
- Phase C release checks: flat-layout wheel/sdist build with `SETUPTOOLS_SCM_PRETEND_VERSION=0.1.0`, staged artifact installation smoke, CI workflows, and bounded alignment work.
- Phase D documentation/tests: timing boundary and doctor semantics, stable normalization profiles and language limits, and Unicode/caption edge cases.

## Required external gates still open

1. **Real Redux inference:** Not run. The local Moondream 0.2.0 installation is below SpeechScope's declared `>=2.4.1` minimum, and no rights-cleared audio fixture was available. The real CPU test remains opt-in; mocked tests and metadata-only `doctor` are not live-model evidence.
2. **CI and SDK matrix:** Workflows were added and YAML-parsed locally, but GitHub Actions has not run. Python 3.11/3.12/3.13 CI and the Moondream 2.4.1/2.6.1 contract matrix remain unverified.
3. **Twine:** `python -m twine check` cannot load Termux's `nh3` extension (`PyExc_TypeError` unresolved; `check-0105`). The staged artifacts have not passed Twine locally; the Ubuntu CI artifact job must provide that evidence.
4. **Clean dependency install on this host:** The Android/Termux Python 3.14 environment has no compatible NumPy wheel; the attempted clean install fell back to a source build that fails in NumPy's complex-math compilation (`check-0030`). Linux clean installs are specified in CI but have not run.
5. **Tag-derived artifact:** No Git tag was created. The successful `0.1.0` artifacts used a staging version override and do not establish a tag-derived release build.

Do not claim model, hardware, cross-platform, GitHub Actions, Twine, or publication validation from the local checks above. Revisit the no-go decision only after the real CPU gate and clean Linux CI/artifact/Twine gates pass. Keep tagging and publishing outside this implementation task.
