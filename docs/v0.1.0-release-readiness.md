# SpeechScope v0.1.0 release readiness (unreleased)

**Decision: NO-GO for tagging or publishing.** The v0.1.0 comparison and release-preparation implementation is complete in this working tree, but it has not been validated by hosted CI or a release tag. No v0.1.0 tag or PyPI publication has been made. The initial [changelog](changelog.md) is generated as **Unreleased**.

## Comparison contract

Conventional whitespace-tokenized WER/MER/WIL/WIP remain unchanged. The separate bounded compound protocol allows deterministic adjacent split/join matches of up to three tokens, reports counts and visible boundary spans, and supports `max_compound_wer`. The supplied Piper pair should report strict WER `2/19`, compound WER `0`, CER `0`, one visible boundary variant, and `content_match=true`. The regression and policy tests pass locally. The protocol and report schema are documented in [`comparison.md`](comparison.md) and [`report-schema.md`](report-schema.md); report schema version remains `1`.

## Supplied live Redux evidence

The audit brief reports one real inference run with Moondream 2.6.1 and `moondream/parakeet-redux`, using CPU and WAV input, with native word timestamps. This remains supplied evidence for that setup, not an independently reproduced test or a compatibility guarantee. Timestamp projection is conservative: one native `end-to-end` span does not establish separate timings for normalized `end`, `to`, `end` tokens.

## Release gates still open

1. **Hosted CI and supported platforms:** the Ubuntu Python 3.11/3.12/3.13, minimum-dependency, Windows/macOS smoke, artifact, and SDK-compatibility workflows are configured but have not run on GitHub.
2. **Dependency compatibility:** the minimum NumPy/SoundFile/Audiosig job and Moondream 2.4.1/latest-supported-2.x contract jobs require hosted results.
3. **Real Redux inference:** run the opt-in CPU integration with an operator-supplied rights-cleared WAV, known transcript, and rights record; verify plausible native word timing. The supplied report does not substitute for this reproducible gate.
4. **Release artifacts:** on the exact release tag, pass Linux wheel/sdist installation and CLI smoke checks plus `twine check`. Local artifact construction and packaging-content tests do not satisfy this gate.
5. **Publication:** configure PyPI Trusted Publishing identity and environment permissions outside the repository, then publish only from an approved semantic tag and verify a fresh install. This implementation adds the gated workflow but does not configure PyPI or publish.

Do not claim hosted CI, platform support, a clean dependency install, Twine success, tag-derived artifacts, live-model reproducibility, or publication until corresponding evidence exists. Keep the release **NO-GO** until required gates are green. Tagging and publication remain out of scope for this task.
